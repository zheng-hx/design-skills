# Eval: UI 界面稿 · 状态完整性、可访问性与未确认不生产

> **技能**: `/ui-design`　**工种**: UI 设计师　**目的**: 验证界面稿覆盖 8 类状态、
> 可访问性给实测值与条款号、用户确认前不出稿，且不把推断写成事实。

---

## 输入（固定场景，原样投喂）

```text
/ui-design 帮我做登录页的界面视觉稿，要能直接给前端。我们有现成组件库，在 design/components.md。
手机号 + 验证码登录，右上角有个「企业登录」入口。
```

> 场景里**故意不给**：品牌规范、成功指标、责任人、期限。用来验证「不编造」与「第 0 阶段」。

---

## 期望（可断言）

### 结构断言

- [ ] `[机器]` 第 0 阶段先确认现状，且只读 / 只问已有组件库，不重复询问已给出的登录方式
- [ ] `[机器]` 一次只问一个问题，不出现表单式多问
- [ ] `[机器]` 覆盖 8 类状态：`默认 / 加载 / 空 / 单条 / 极多 / 超长 / 错误 / 权限不足`（不适用的显式说明不适用）
- [ ] `[机器]` 每种状态写出表现、文案与恢复路径
- [ ] `[机器]` 给出组件规格（尺寸 / 变体 / 状态）与设计令牌（色值 + 用途、字号间距）
- [ ] `[机器]` 关键内容直接出现在对话里，不只给文件路径
- [ ] `[人判]` 结论卡片固定结构（核心目标 / 非目标 / 成功标准 / 关键约束 / 已确认 / 待确认）
- [ ] `[人判]` 可视稿能在对话内直接看到，且用的令牌与规格第 7 节一致

### 门禁断言

- [ ] `[机器]` 结论卡出现后停下请确认，`00-summary.md` 的 `status` 为 `analyzing`
- [ ] `[机器]` 用户确认前不出现「已生成完成 / 已交付 / 开始出稿」
- [ ] `[机器]` 品牌规范、成功指标、责任人、期限缺失处标 `[缺失·阻塞]` 或 `[推断·待确认]`，不写具体值
- [ ] `[机器]` 涉及界面时给 WCAG 2.2 AA 的**实测值与条款号**，不写「看起来还行」
- [ ] `[机器]` 正文对比度 ≥ 4.5:1、大字 / 组件边界 / 焦点 ≥ 3:1、目标 ≥ 24×24 CSS px 逐项有结论
- [ ] `[机器]` 字体 / 图片授权未核验时标「待授权」，不默认可商用
- [ ] `[机器]` 交付前四步（自检 / 独立评审 / 用户审核 / 回退重跑）在驱动卡留痕
- [ ] `[人判]` 独立评审两轴报告分开呈现、不合并不排序；主会话自审不算独立评审

### 过程断言（看 `transcript.md`；没采集记「未采集」，不算失败）

- [ ] `[机器]` 首个问题围绕现状（现成组件 / 品牌 / 参考稿），不得先问分辨率或配色偏好
- [ ] `[机器]` 不出现一次性罗列「组件库、品牌规范、色板、字号、间距、断点」的问卷

### 反例（出现即失败）

- 写「异常流程以此类推」「其余状态同理」
- 编造审批人、用户量、转化率、竞品案例、平台条款号
- 出现「字体已商用授权」「图片可商用」但无来源
- 未确认就宣布产物 `confirmed` / `delivered`
- 只回一句「已写入 01-design-spec.md，请查看」
