# 开源资料与致谢

> 本包从 GitHub 上的设计类 Agent Skills 项目里**调研方法、借鉴结构**，并按许可分级决定借鉴深度。
> 运行时清单由 `build-disciplines.py` 从 `disciplines.json` 的 `sources` 聚合生成，见
> `.design/references/开源资料索引.md`；许可红线见 `.design/references/许可与来源规范.md`。

---

## 1. 许可红线（先说这个）

| 许可状态 | 允许做什么 | 禁止做什么 |
|---|---|---|
| **MIT / Apache-2.0** | 借鉴具体的规则表达、检查表结构、章节组织；保留出处 | 原样整仓搬运、去掉许可声明 |
| **官方示例**（anthropics/skills） | 借方法论与命名约定 | 当成规范条文引用 |
| **待核实 / 无 LICENSE / NC-SA** | **只借方法论**，即「它解决什么问题、按什么顺序」 | 搬文字、搬模板、搬提示词、搬代码 |

红线落在三处，互相兜底：

1. `.design/rules/设计通用规范.md` §4「授权与来源」——运行时行为约束；
2. `.design/references/许可与来源规范.md`——细化到「什么算搬、什么算借」；
3. `.design/references/开源资料索引.md`——每个工种挂了哪些来源、什么许可。

**外部规则与本包门禁冲突时，以 `.design/rules/设计通用规范.md` 为准。**

## 3. 落进本包的哪几处

| 文件 | 整合了什么 |
|---|---|
| `.design/references/数字产品质量基线.md` | UI / UX / 设计系统 / 可访问性 / 状态完整性的可执行检查表 |
| `.design/references/视觉与品牌基础.md` | 色彩、字阶、构图网格、品牌应用矩阵 |
| `.design/references/立体与空间交付边界.md` | 3D 可交付配置 vs 实体不可交付物的分界 |
| `.design/references/可访问性细则.md` | WCAG 2.2 AA 逐条口径（**逐字复用**自内部规范） |
| `.design/references/AI生成设计缺陷清单.md` | AI 出图常见缺陷自查（**逐字复用**自内部规范） |
| `.design/references/工种通用流水线.md` | 长尾工种 8 步通用流水线 + 边界声明模板 |
| `.design/references/许可与来源规范.md` | 本文第 1 节的运行时版本 |
| `.design/references/开源资料索引.md` | 由注册表 `sources` 自动聚合，请勿手改 |
| `.design/rules/设计通用规范.md` | 本包自己的红线，优先级最高 |

**接入规则**（三条，防止把外部内容整包塞进来）：

1. 新增参考文件必须登记进 `disciplines.json` 的 `shared_references`，否则渲染校验判为死文件；
2. 只搬「可检索的规则 / 结构 / 检查表」，不整包塞进技能目录——工种包是自包含的，整包塞会串引用、破校验；
3. `sources` 只记方法论出处，**不构成法律意见**；商业使用前请自行复核上游许可。
