## 架构收敛结论（不再反复讨论）

1. **单角色多工种**：一个项目一个设计师技能包，包内按工种分技能；不做「一个项目一个角色」的 5 选 1。
2. **分层交付**：37 个工种不都做成技能。30+ 斜杠命令会让触发词互相抢；
   室内 / 建筑 / 服装 / 珠宝这类工种的施工图、打样件、可印制原文件 AI 给不出来，
   做成完整技能等于**假交付**。索引登记 + `/design-any` 兜底 + 第 0 步边界声明，覆盖到了也不撒谎。
3. **注册表是单一事实源**：改工种只改 `disciplines.json` 再跑生成器，禁止手改生成物。
4. **扫描到的全装**：多 AI 工具并用时每个检测到的目录都注册，未检测到的一律不写、不创建。
5. **引擎复用但必须对齐**：复用旧包规则时同步改产物路径与措辞，并由 `validate-package.py` 第 8 项拦截残留。
6. **用户区神圣不可侵犯**：`.design/artifacts/` 升级绝不覆盖，用户自己的技能与其他包的注册项绝不清理。

## 明确不做

- **不做后端 / 数据库 / MCP**：本包是纯本地文件形态的技能包，产物是 `.design/` 下的 Markdown / JSON。
- **不内置 37 份完整流水线**：理由见「架构收敛结论」第 2 条。
- **不替用户生成实体交付物**：施工图、CAD / BIM、打样件、可印制原文件、材料验算、资质报审一律声明给不出。
- **不硬编码仓库地址 / 不猜 API key**：拿不到就报错，不发明。
- **不自动评分「设计好不好」**：机器断言只判结构 / 门禁 / 禁语，审美与判断力归人。
