# 工种全景（4 域 37 工种）

> **权威源**：`skills/apply-design-skills/capabilities/design-core/disciplines.json`（单一事实源）。
> 本文是人读概览；改工种只改 JSON，再跑 `build-disciplines.py` 重生成模板与索引。
> 运行时清单见渲染后的 `.design/references/工种索引.md`。

## 分层口径

| 层 | 数量 | 形态 | 怎么调用 |
|---|---|---|---|
| `core` | 19 | 独立 `SKILL.md` + 专属流水线 / 产物 / 参考路由 | 直接 `/<工种 key>` |
| `extended` | 18 | 只登记索引，不给独立技能 | `/design-any <工种名> <需求>` |
| 入口 / 兜底 | 2 | 手写入口技能 | `/design-router`、`/design-any` |

**为什么不都做成技能**（这是本包最重要的取舍）：

1. **触发词互相抢**：30+ 斜杠命令，用户说「帮我做设计」时模型很难选对；`check-triggers.py` 也拦不住语义级重叠。
2. **假交付**：室内、建筑、工业、服装、珠宝这类工种的最终交付物是施工图、打样件、可生产文件，
   AI 给不出来。做成「完整技能」等于承诺做不到的事。
3. **维护成本**：37 份完整流水线，改一次公共门禁要同步 37 次。

所以做法是**清单收录 + 通用兜底 + 边界声明**：覆盖到了，也不撒谎。`/design-any` 第 0 步会强制列出
「我能给什么、不能给什么」。

## 怎么新增一个工种

1. 改 `disciplines.json`：加 `key` / `name` / `en` / `domain` / `tier` / `triggers` / `summary`；
   `core` 还要给 `pipeline` / `artifacts` / `references` / `sources`。
2. 触发词全局不能重复（生成器与 `check-triggers.py` 都会拦）。
3. 跑 `python3 skills/apply-design-skills/scripts/build-disciplines.py` 重生成模板与索引。
4. 引用了新的参考文件 → 先建文件并登记进 `shared_references`，否则渲染校验判死文件。
5. 跑 `npm run check:all`；`--check` 会确保生成物与注册表不漂移。
