# 设计通用规范（全工种红线）

> **作用域**：所有设计工种。工种自己的 `SKILL.md` 只写差异，不重复这里的红线。
> **优先级**：外部开源规则与本文件冲突时，以本文件为准。

## 1. 第 0 阶段：先确认现状（硬门禁）

每个工种的第 0 阶段都是「确认现状」，只是问的东西不同：

| 域 | 必问 |
|---|---|
| 数字产品 | 现成产品 / 设计系统 / 组件库 / 品牌规范 / 参考稿 / 技术栈 |
| 平面品牌 | 媒介 / 尺寸 / 品牌规范 / 交付格式 / 字体与素材授权 |
| 空间与实体 | 场地 / 尺度 / 材料 / 工艺 / 法规与资质约束 |
| 商业与新兴 | 平台规则 / 商品或业务信息 / 现有素材 / 合规禁用项 |

- 一次只问**一个**最该问的问题；**拿不到就停**，不许 best-guess 视觉方向、品牌、对外承诺与业务规则。
- 用户口述、粘贴、截图都是来源，按《产物与来源规范》§6 原样落盘 `sources/`，记出处与日期。

## 2. 收口与状态机

- 收敛时**对话内先出结论卡片** → 落盘 `00-summary.md`（`status: analyzing`）→ 请用户确认。
- **人类确认是进入生产的唯一钥匙**：确认后才改 `producing`，不得擅自写「开始出稿」「已完成」。
- 单产物 `draft → proposed → reviewing → confirmed → delivered`；上一阶段 `confirmed` 才进下一阶段。
- 门禁不过就退回或请示，不跳步。

## 3. 不编造（QA 级红线）

| 类别 | 没来源时怎么写 |
|---|---|
| 审批人、责任人 | `[缺失·阻塞]` |
| 数据、用户量、转化率、调研结论 | `[缺失·阻塞]`，不写具体数字 |
| 金额、预算、期限、SLA | `[缺失·阻塞]` |
| 竞品案例、行业惯例 | 不编案例；引用必须给可核对的出处与日期 |
| 平台规则、法规条款 | 不臆造条款号；不确定就标「待核验」 |

**禁止把推断写成事实**。推断要显式标 `[推断·待确认]`。

## 4. 授权与来源（设计工种特有）

- **字体**：核对授权范围（商用 / 嵌入 / 分发 / 改作），拿不到就标待授权，不默认可用。
- **图片与图库素材**：记录来源、许可、是否需署名；不得把无 LICENSE 素材当可商用。
- **开源资料**：MIT / Apache-2.0 可借鉴具体表达与结构；`待核实` / NC-SA / 无 LICENSE 只借方法论，
  不搬文字与模板。详见 `references/许可与来源规范.md` 与 `开源资料索引.md`。
- **参考稿**：用户提供的参考稿只在本次项目内使用，不外传、不写进对外交付物。

## 5. 可访问性是底线（涉及界面时）

- 基线 **WCAG 2.2 Level AA**，不用 WCAG 3.0 草稿或 APCA 作为通过标准。
- 正文对比度 ≥ 4.5:1，大字 / 组件边界 / 焦点 ≥ 3:1，目标尺寸 ≥ 24×24 CSS px。
- 逐条给**实测值与条款号**，禁止用「看起来还行」代替。详见 `references/可访问性细则.md`。

## 6. 状态完整性（最常见的返工来源）

任何界面方案都要覆盖 8 类状态，缺一类就退回：
`默认 / 加载 / 空 / 单条 / 极多 / 超长 / 错误 / 权限不足`。
禁止「异常流程以此类推」，每条分支都要写清路径与恢复方式。

## 7. AI 生成物的排查

用宿主原生生成能力或外部模型出图时，出稿后逐项过 `references/AI生成设计缺陷清单.md`，
至少回答自查三问（这是什么 / 空白在哪 / 出错了会怎样）。
**采用 AI 常见痕迹必须有品牌或场景上的理由**，不能因为「好看」就留着。

## 8. 交付边界（不许假交付）

| 能交付 | 不能交付（必须如实说明） |
|---|---|
| 简报、方案、规格、检查清单、可评审文档、可复现的配置与提示词 | 施工图 / CAD / BIM、打样件、可印制原文件、材料与结构验算、资质报审 |

`extended` 工种一律先说明边界再开工，见 `/design-any`。

## 9. 交付前四步与独立评审

**AI 自检 → 独立评审 → 用户审核 → 回退重跑**。
独立评审派**只读**子智能体分 Spec / Standards 两轴，不合并不排序；
宿主无子智能体原语时另开会话顺序两遍并**标注「降级模式」**；**主会话自审不算独立评审**。

## 10. 对话内展示

关键内容——结构、状态、视觉语言、组件规格、结论卡片、路由卡——**必须出现在对话里**。
只给文件路径等同于没交付。

## 11. 交付最小集（全工种硬门禁）

**不分工种，任何交付物都要同时回答通用四问，缺一即未完成：**

| # | 四问 | 含义 |
|---|---|---|
| 1 | **结构** | 它由什么组成、怎么组织，看得懂 |
| 2 | **呈现** | 能直接看到成品本身（图 / 稿 / 模型 / 预览），不是只有文字 |
| 3 | **规格** | 别人能照着做出来：尺寸、参数、变体、状态、材料 |
| 4 | **语言** | 一致的调性与规则，并说明为什么适合 |

再叠加**本工种最小集**（各工种清单见 `{{DESIGN_ROOT}}/references/交付最小集.md`）。
示例：界面类四样 = 页面结构 / 页面效果（可视稿）/ 组件规格（变体+状态）/ 视觉语言 7 项。
「给了页面 / 给了稿」不算交付；只给文件路径不算交付。

## 12. 门禁与硬指标（完成定义）

**完成定义**（全工种逐条勾，任一不满足即未完成）：

- [ ] 设计问题可验证，非目标明确
- [ ] 现成产品 / 设计系统 / 品牌资产已确认，或明确记为「没有」
- [ ] 主流程、分支、异常与恢复路径完整
- [ ] 必要状态有设计（涉及界面：loading / empty / error / disabled / success / permission / 离线 / 溢出）
- [ ] 本工种最小集齐全（`{{DESIGN_ROOT}}/references/交付最小集.md` 对应行逐项打勾）
- [ ] 规格可验证，不用「美观 / 大气 / 高级」当验收条件
- [ ] 文案 / 说明齐全，错误信息说清「怎么办」
- [ ] 字体、图片、素材、参考稿授权已核对，未授权项已标待授权
- [ ] 设计评审有结论与责任人
- [ ] 可用性 / 效度 / 打样等验证有证据，或明确记为「未执行」

**硬指标（界面类，可验证，不用形容词）**：

| 维度 | 要求 |
|---|---|
| 正文 | ≥ 16px，行高 1.4–1.6，每行 50–75 字符 |
| 对比度 | 正文 ≥ 4.5:1；大字与组件边界 ≥ 3:1 |
| 间距 | 全部取自同一套 4px 或 8px 网格 |
| 反馈 | 100ms 内可见反馈 |
| 过渡 | 常规 150–300ms；仅大范围动效可到 500ms |
| 动效偏好 | 必须尊重 `prefers-reduced-motion` |
| 触控 | 目标 ≥24×24（AA），推荐 ≥44×44 |
| 禁用态 | 必须说明原因 |

> 非界面工种取本工种的可验证指标（如印刷：出血 3mm、CMYK、字体转曲；包装：刀版标注与材料克重；
> 标志：最小尺寸与安全边距），写进本工种产物，不套用上表。
> 完整条款见 `{{DESIGN_ROOT}}/references/可访问性细则.md`。

## 13. 失败模式（对照自查）

| 失败模式 | 症状 | 纠正 |
|---|---|---|
| 凭空「复用现有」 | 没确认就写沿用现有组件 | 先找或先问，拿不到就写「没有」 |
| 交付偏门 | 只有交互规格，没有视觉语言、组件、图标 | 按 §11 补全 |
| 只有页面没有组件 | 给了页面结构，没写按钮/字号/尺寸/状态 | 逐组件补规格表 |
| 只有文字没有效果 | 交付里一张图都没有 | 出可视稿（截图 / SVG / HTML） |
| 自己拍风格 | 用户没说，直接画了一套 | 给 3 个候选方向让人选 |
| 只画 happy path | 空/错/权限/离线全靠线上暴露 | 按 §12 状态清单补齐 |
| 视觉稿没法看 | 出的图是线框工具风 | 先定视觉方向再出图 |
| 只给链接 | 用户要自己点开才看到 | 关键内容直接贴进对话 |
