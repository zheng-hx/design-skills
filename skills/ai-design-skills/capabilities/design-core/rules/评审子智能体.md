# 评审子智能体

> **作用域**: 工种无关的引擎。所有工种的自包含技能包都带这一份（可被工种同名覆盖）。
> **状态**: 强制
> **硬边界**: 子智能体**不参与开发**——不写代码、不改被测系统、不修缺陷、不搭自动化框架、不部署。
> 它只处理**本工种的产物**（用例、执行记录、报告、方案、规格…），结论是给人的输入，不是放行。
> **可选性**: 本包所有工种**统一启用** A 类评审型（见 `{{DESIGN_ROOT}}/rules/设计通用规范.md` §9 交付前四步）；
> B / C 类默认不用，除非本工种在自己的 `SKILL.md` 里显式写清边界。
> **启用即一致**: 只要工种启用了评审，**流程必须按本文件走**，不得自创另一套。

---

## 0. 为什么要独立评审

主会话的「AI 自检」是**作者视角**，盲区与写的人共享——自己给自己打分，问题容易被同一套理由掩盖。

所以要有一层**独立评审**：由**不共享本次上下文**的评审者，按固定检查清单重读产物。

> **主会话自审不算独立评审。** 这句话是本节最重要的一条，任何降级路径都不例外。

---

## 1. 三类子智能体（先分清，再谈派发）

| 类型 | 干什么 | 是否碰"执行" | 是否启用 |
|---|---|---|---|
| **A. 评审型** | 双轴评审本工种产物（见 §2） | 只读 | **由工种声明**（可以不要） |
| **B. 执行型** | 跑本工种职责内的可执行环节（如可访问性设计师跑对比度实测、UI 设计师跑状态走查） | 只读 + 产出记录 | 由工种声明；**未写清边界即不可用** |
| **C. 取证型** | 去收集一手证据（调研、抓取、核验来源） | 只取证据 | 由工种声明 |

**本引擎只提供机制，不替工种做选择。** 每个工种在自己的清单里声明启用哪几类（可以一类都不启用）；**启用了就必须按本文件执行**。

**三类共同的红线**（命中即停）：

- 不写代码、不改被测系统、不修缺陷、不搭自动化框架、不部署；
- 只读产物，**不得**修改产物文件；
- 子智能体的**自述不算证据**（与本库《测试规范》一致）；
- 子智能体**不得**代替人拍板，也不得宣布"可发布/可上线"。

---

## 2. 双轴评审（核心机制）

把评审拆成两个**互不可见**的轴，各自独立跑、分开出报告：

| 轴 | 对照什么 | 回答什么问题 |
|---|---|---|
| **Spec 轴** | 该工种的**规格来源**（需求 / AC / 简报 / 接口文档 / 客户原话…） | 该做的做了吗？做了不该做的吗？ |
| **Standards 轴** | 该工种的**规范与门禁**（本工种规范 + 红线条款） | 合规吗？有没有踩红线？ |

**为什么必须分开**：一个轴查"对不对需求"、另一个轴查"合不合规范"，混在一起会互相掩盖（"需求做对了但完全不合规范"和"规范没问题但需求做歪了"是两种病）。

两轴的具体来源：Spec 轴看本工种流水线表与 `00-summary.md` 的本轮结论；Standards 轴看
`{{DESIGN_ROOT}}/rules/设计通用规范.md` 与 `{{DESIGN_ROOT}}/references/` 里按工种路由表命中的那几份参考。

---

## 3. 派发契约（宿主有原语时）

1. **独立上下文**：只给"要读的文件 + 检查单 + 输出格式"，**不给**主会话历史，避免被主会话的判断锚定。
2. **只读**：禁止写任何产物、禁止改代码、禁止执行有副作用的操作。
3. **一次并行派发两个只读子任务**（Spec / Standards）；**禁止**串行合并为单任务。
4. **聚合时不合并、不排序**：报告分 `## Spec 轴报告` / `## Standards 轴报告` 两节**原样呈现**。
5. 每个子智能体**不得再派生**下级子智能体。
6. 每条发现必须带**引用**（产物章节 / 条款 / 用例号 / 行号），无引用视为无效发现。

用哪个原语由宿主决定（Reasonix `parallel_tasks`、Claude Code Task tool、Codex Agent 等），本引擎不绑定具体工具。

---

## 4. 无原语时的降级（必须标注）

宿主不提供子智能体能力时：

- 降级为**另开新会话**，顺序跑两遍（先 Spec 轴、再 Standards 轴）；
- **必须在评审表里标注「降级模式」**，不得伪装成双轴独立；
- 降级路径**同样**要求两轴分节、每条发现带引用；
- **主会话自审不在降级之列**——它不算独立评审。

---

## 5. 报告结构（机械可校验）

```markdown
## 概述
- 评审范围：<评了哪些产物、哪些没评>
- 评审方式：独立子智能体（双轴并行） / 降级模式（另开会话）
- 🔴 严重问题：N ／ 🟡 建议改进：N ／ 🟢 通过：N

## Spec 轴报告（规格匹配）
### 🔴 严重问题
- <问题> — 引用：<产物章节 / 条目 / 行号>
### 🟡 建议改进
### 🟢 通过项

## Standards 轴报告（规范合规）
### 🔴 严重问题
- <问题> — 引用：<规范条款 / 门禁条目>
### 🟡 建议改进
### 🟢 通过项

## 结论
<0 个 🔴 → 可进入用户审核；有 🔴 → 退回上游重跑>
```

**结构要求**（缺一即视为评审未完成）：两轴分节、概述含评审范围与评审方式、每条 🔴 带引用。

---

## 6. 分级与放行

| 级别 | 含义 | 处置 |
|---|---|---|
| 🔴 严重 | 违反规格、违反门禁、破坏红线 | **必须修复**，0 个 🔴 才可推进 |
| 🟡 建议 | 可优化但不阻塞 | 记录，自行决定是否修 |
| 🟢 通过 | 已核对通过的项 | 留痕 |

- 有 🔴 → **退回上游重跑**（按状态机回退，不跳级），评审报告作为修复依据。
- 审计结论落驱动卡 `00-summary.md` 的「独立评审」表，**未填不得进入确认/交付**。
- 降级模式同样按此放行，但必须保留「降级模式」标注。

---

## 7. 红线

- **主会话自审不算独立评审**——作者视角与评审视角必须是两个上下文。
- 子智能体**不得**修改产物、代码或被测系统。
- 子智能体**不得**宣布放行/可发布；结论由人拍板。
- **不得伪装双轴独立**：降级就是降级，必须标注。
- 子智能体自述**不算证据**；发现必须可追溯到产物中的一条引用。
- B 类（执行型）**未在本工种规范里写清边界前不得启用**。
- 工种**未启用**评审时，必须**显式记录**"本工种不设独立评审"及理由，**不得静默跳过**。
