# 评审子智能体清单（全工种通用）

> **作用域**：**所有 core 工种**共用。派发契约、双轴细则、报告结构见引擎 `{{DESIGN_ROOT}}/rules/评审子智能体.md`；
> 本文件只定义「派谁、评什么、拿什么对照」。
> **自包含**：清单为本包自定，不引用任何外部项目或角色包。

## 0. 启用声明

| 项 | 值 |
|---|---|
| 是否启用独立评审 | **是**（全部 core 工种统一启用，不按工种开关） |
| 理由 | 设计产物是最终交付物；可访问性属法定风险；界面、印刷、空间类返工成本高 |
| 启用后流程 | 一律按 `{{DESIGN_ROOT}}/rules/评审子智能体.md`——**启用即一致**，不自创另一套 |

---

## 1. 双轴对照（不分工种）

| 轴 | 对照什么 | 回答什么 |
|---|---|---|
| **Spec 轴** | 设计简报 / 用户与场景 / 流程 / 需求验收条件 | 目标与场景覆盖了吗？有没有做需求外的东西？ |
| **Standards 轴** | `设计通用规范.md` + `交付最小集.md` + 工种专属参考（可访问性 / 视觉与品牌 / 立体与空间交付边界…） | 合规吗？最小集齐吗？硬指标达标吗？ |

---

## 2. 三类子智能体（全工种一致）

| 类型 | 是否启用 | 说明 |
|---|---|---|
| **A. 评审型** | ✅ 启用 | 只读评审设计产物，双轴出报告 |
| **B. 执行型** | ⚠️ 受限启用 | 可访问性逐条核验、界面走查、印前核对；只读，**不写前端代码、不改实现** |
| **C. 取证型** | ❌ 不启用 | — |

---

## 3. A 类 · 通用评审员（每个工种必派）

| 评审员 | 评审对象 | 双轴对照 |
|---|---|---|
| 主产物评审员 | 本工种主产物（如 `design-spec` / 品牌手册 / 分镜 / 研究报告 / 审计报告） | Spec：目标 / 场景 / 流程；Standards：设计通用规范 + 交付最小集 |
| 交付完整性评审员 | 全部产物与收口卡片 | Spec：需求验收条件逐条；Standards：本工种最小集逐项打勾（缺一即 🔴） |
| 可访问性审计员 | 涉及界面的产物 / 截图 | Spec：真实用户场景；Standards：WCAG 2.2 条款级 |

## 4. 按工种追加（有则派，无则免）

| 追加评审员 | 适用工种 | 评审什么 |
|---|---|---|
| 组件一致性评审员 | ui / product / web / systems | 组件规格变体与状态是否写全；令牌用法是否一致 |
| 印前与输出评审员 | graphic / packaging / typography / infographic | 出血、色彩模式、字体转曲、刀版与工艺标注 |
| 品牌一致性评审员 | brand / visual / ecommerce | 标志与标准色用法、应用场景一致性 |
| 研究效度评审员 | research / ux | 样本偏差、结论与证据是否匹配、局限是否写明 |
| 还原与性能评审员 | motion / web / 3d | 时长与缓动、导出规格、降级与性能 |

> 每个评审员派发时都拆成**两个独立只读子任务**（Spec / Standards），两轴**不合并不排序**，报告分两节。

---

## 5. 能评 / 不能评

| 能做 | 不能做 |
|---|---|
| 评审设计产物、逐条核验（含可访问性 / 印前 / 最小集），出问题清单 | 不顺手改稿、**不写前端代码、不改实现**；不宣布放行 |

---

## 6. 派发与降级

流程不在这里重复——一律按引擎 `{{DESIGN_ROOT}}/rules/评审子智能体.md`：

- 独立上下文（fresh subagent）、只读、并行派发两轴、**不合并不排序**；
- 宿主无子智能体原语 → 降级为另开新会话顺序两遍，**必须标注「降级模式」**；**主会话自审不算独立评审**；
- 每条 🔴 必须带引用（产物章节 / 条目 / 行号 / 规范条款）；
- 结论写进驱动卡 `.design/artifacts/<feature-slug>/00-summary.md` 的「独立评审」表；有 🔴 → 退回上游重跑。
