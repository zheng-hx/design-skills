# 视觉与品牌基础

> **作用域**：`visual-design` / `brand-design` / `graphic-design` / `packaging-design` /
> `typography-design` / `illustration-design` / `infographic-design` / `ecommerce-design` /
> `web-design` / `ai-generated-design` 按需加载。
>
> **来源**：品牌系统结构参考通用品牌方法论与官方设计语言规范，配色 / 字体 / 反模式检索结构借鉴公开的设计实践；
> 本包不引用任何具体外部项目，均为自包含整理。

## 1. 先定调，再画

视觉方向不是「选个好看的配色」，而是一组**可复用、可判断**的决策：

| 决策 | 必须回答 | 落到哪 |
|---|---|---|
| 定位 | 品牌关键词 / 情绪 / 受众 / 竞品差异 | 简报 |
| 符号 | 标志方向、可识别性、变体 | 标志方向 |
| 色彩 | 主色 / 中性阶 / 语义色 / 明暗两套 | 色彩系统 |
| 字体 | 中英文字体、字阶模数、授权范围 | 排版规范 |
| 图形 | 图形语言、质感、摄影 / 插画调性 | 视觉规范 |
| 应用 | 各媒介的尺寸、安全区、禁用示例 | 应用矩阵 |
| 反模式 | **绝对不要做什么** | 品牌手册 |

> 没有「反模式」一节的视觉规范等于没写——它才是防止后续走样的那道闸。

## 2. 色彩系统

- 结构：`主色 + 中性色阶 + 1 个语义色`起步，别一上来堆十几个颜色；
- 每色给出**用途**与**不可用场景**（例如「主色不用于大面积背景」）；
- 明暗两套各自验证对比度，浅色模式达标不代表深色模式达标；
- 色值记录格式（HEX / RGB / OKLCH）与转换口径，避免交付时各写各的；
- 图表配色要单独考虑色觉缺陷可辨识，不能只靠红绿区分。

## 3. 字体与排版

- **授权先核**：商用 / 嵌入 / 分发 / 改作，四项都要确认；拿不到就标待授权；
- 中英混排要写清基线、字重映射、标点与断行规则；
- 字阶用模数（如 1.25）推导，不逐档手调；
- 行高、字距、最大行宽给出数值，不写「适中」；
- Web 场景要有字体加载失败时的降级栈。

## 4. 品牌手册最小结构

不追求几百页，够用即可：

```text
1 定位与关键词        2 标志与变体 / 安全区 / 禁用示例
3 色彩系统            4 字体与字阶
5 图形与图像调性      6 组件与版式示例
7 应用矩阵（媒介×尺寸）8 语气与文案口径
9 反模式清单          10 资产清单与版本记录
```

## 5. 平面与版式

- 先定**信息层级**，再定网格；不是反过来；
- 网格、安全区、出血位、裁切余量写数值；
- 多尺寸延展时先做最受限的那个尺寸，再往大尺寸放；
- 印前核对：色彩模式、分辨率、出血、字体转曲、专色与工艺标注。

## 6. 包装 / 空间图形特有

- 结构（刀版）先于视觉：没有结构尺寸的视觉稿无法落地；
- 法规信息位（成分、条码、警示语）是**硬约束**，不能被视觉挤掉；
- 货架识别看的是 1–3 米外的轮廓与色块，不是近看的细节；
- 材质与工艺会改变颜色呈现，方案里要标注需打样确认的项。

## 7. AI 生成视觉的排查

用宿主原生生成能力或外部模型出图时：

1. 提示词拆成「主体 / 构图 / 光线 / 色彩 / 质感 / 风格 / 排除项」可复现的结构，并留版本号；
2. 出稿后逐项过 `AI生成设计缺陷清单.md`，回答自查三问；
3. 品牌一致性要人工确认：标志、标准色、字体**不能靠模型猜**；
4. 来源与授权记录要落盘，见 `许可与来源规范.md`。

## 8. 交付检查

| # | 项 |
|---|---|
| 1 | 反模式清单已写，且每条可判断 |
| 2 | 明暗两套对比度都实测过 |
| 3 | 字体授权四项已核，未授权项已标待授权 |
| 4 | 应用矩阵覆盖用户实际要用的全部媒介与尺寸 |
| 5 | 资产清单含版本、格式、色值口径 |
| 6 | 规格写成可验证表述，不写「大气」「有质感」 |
