# 数字产品质量基线

> **作用域**：数字产品域所有工种（`ui-design` / `ux-design` / `interaction-design` /
> `product-design` / `visual-design` / `web-design` / `motion-design` / `systems-design` /
> `accessibility-design` / `design-research`）出稿与评审时按需加载。
>
> **来源**：结构化检查表参考公开界面质量方法论（风格 / 配色 / 字体 / UX 准则 / 交付前检查），
> 排版与状态口径借鉴通用设计系统实践；均为本包自包含整理，不引用任何外部项目。

## 0. 先定系统，再出稿

开源资料里最有价值的一条共识：**AI 生成界面缺的不是代码，是可查询的设计约束**。
所以顺序固定为：

```text
现状探测 → 风格 / 行业规则 → 色板与令牌 → 字体与字阶 → 布局与组件 → 出稿 → 交付前检查
```

**不要跳到出稿**。跳过定系统，结果就是紫粉渐变 + 卡片套卡片 + emoji 当图标的默认 AI 味。

现状探测至少核对：CSS 变量、Tailwind / token 文件、UI 框架主题、组件目录、Storybook、
字体加载、包依赖。**尊重已有系统，不另造一套组件、不撞色**。

## 1. 界面质量检查表（出稿后逐项过）

| 轴 | 检查项 | 通过标准 |
|---|---|---|
| **对比与色彩** | 语义色板、格式转换、对比度实测 | 正文 ≥4.5:1，组件边界 ≥3:1；语义色不靠猜 |
| **排版** | 字阶、行高、字距、换行、截断、标点 | 有模数；长文本与多语言不破版 |
| **布局** | 分组、对齐、阅读顺序、响应式、译文余量 | 缩放 / 翻译 / 镜像后仍成立 |
| **界面打磨** | 圆角、光学对齐、阴影层级、图标状态、动效 | 有令牌，不逐个手调 |
| **文案** | 标签、报错、空态、确认语 | 写清结果，不写「确定」「操作失败」 |
| **可访问性** | 键盘、焦点、ARIA、可访问名、屏幕阅读器、动效、缩放 | WCAG 2.2 AA 逐条，见 `可访问性细则.md` |
| **构建与还原** | 从设计稿 / 图片还原时复用现有令牌与组件 | 不新建重复组件 |

## 2. 组件状态覆盖（最常见的返工来源）

`break` / `state-machine` / `variant` 这三个思路值得学：**把组件放到临时页里，把它能到达的每种状态都渲染一遍**。

| # | 状态 | 必查 |
|---|---|---|
| 1 | 默认 | 主路径可读 |
| 2 | 加载 | 骨架 / 进度，不白屏 |
| 3 | 空 | 空态文案与首个动作 |
| 4 | 单条 | 边界值不塌 |
| 5 | 极多 | 分页 / 虚拟滚动 / 性能 |
| 6 | 超长 | 多地区姓名、特殊字符、长 URL |
| 7 | 错误 | 三段式：发生了什么 + 为什么 + 怎么办 |
| 8 | 权限不足 | 不是空白页，说明如何获得权限 |

> 禁止「异常流程以此类推」。每条分支都要写清路径与恢复方式。

## 3. 变体与迭代

- 一次给 2–3 个**结构上不同**的变体，不是换色；
- 用真实长度的数据，不用「张三 / test@test.com」这种完美示例；
- 用户选定后才深化，不在未拍板时铺开全部细节。

## 4. 交付前检查（Pre-delivery Checklist）

| # | 项 | 判定 |
|---|---|---|
| 1 | SVG 图标替代 emoji | 是 / 否 |
| 2 | 悬停与聚焦反馈齐全，焦点不被遮挡 | 是 / 否 |
| 3 | 对比度全部达标（附实测值） | 是 / 否 |
| 4 | 响应式断点（375 / 768 / 1024 / 1440）逐档看过 | 是 / 否 |
| 5 | 动效 200–300ms，且有 `prefers-reduced-motion` 降级 | 是 / 否 |
| 6 | 8 类状态全覆盖 | 是 / 否 |
| 7 | 触控目标 ≥24×24（推荐 44×44） | 是 / 否 |
| 8 | 规格写成可验证表述，不写「美观」 | 是 / 否 |

任何一项「否」都不能进入用户审核。

## 5. 行业规则怎么用

开源规则库通常按「产品类型 → 风格 / 配色 / 落地页模式 / 字体 / 反模式」组织，用本地脚本检索，
不联网、不依赖外部 API。**借鉴的是这个结构**，不是把别人的 CSV 原样塞进本包：

- 推理输入：产品类型、受众、品牌约束、技术栈；
- 输出：Pattern / Style / Colors / Typography / Effects / **Anti-patterns** / 交付前检查；
- 最关键的是 **Anti-patterns**——明确写出「这个行业绝对不要做什么」，比给一堆正面示例有用。

## 6. 反模式清单（默认 AI 味）

紫粉渐变主色、玻璃拟态、发光阴影、圆角一律拉满、什么都包卡片、卡片套卡片、
emoji 当图标、每段都居中、应用内塞 hero 区、只画 happy path。
逐项展开见 `AI生成设计缺陷清单.md`。**采用这些痕迹必须有品牌或场景上的理由**。
