# 许可与来源规范

> **作用域**：所有工种。用开源资料、字体、图片、素材、AI 生成物之前先读这份。
> **优先级**：与任何外部开源项目的说明冲突时，以本文件为准。

## 1. 许可红线（硬约束）

| 许可 | 可以 | 不可以 |
|---|---|---|
| **MIT / Apache-2.0** | 借鉴具体表达、结构、检查表；可改写后落地 | 去掉版权与许可声明；误标为自己的原创 |
| **CC BY-NC / NC-SA** | 只看**方法论与结构** | 搬文字、模板、示例；商用 |
| **标注「待核实」** | 只当线索，先核实许可再用 | 当已授权使用 |
| **无 LICENSE** | 只当思路参考 | 搬任何具体表达 |
| **官方 skills / 厂商示例** | 按官方声明使用；借鉴方法论 | 假定可自由商用，先读官方 LICENSE |

> 「借鉴方法论」= 学到「应该先定系统再出稿」这类思路；
> 「搬文字」= 把别人的检查表原文复制进本包。**这两件事必须分清。**

## 2. 外部资料接入状态

本包默认**不引用任何外部开源项目**；全行业工种的方法论、结构、检查表均为本包独立整理。
若需要引入外部资料，按第 1 节红线核验许可后，登记进 `disciplines.json` 并在本表记录。

| 项目 | 许可 | 状态 |
|---|---|---|
| （当前未登记任何外部项目） | — | 本包内容均为自包含整理 |

## 3. 字体 / 图片 / 素材授权四项

用任何第三方资产前，逐项核对并记录：

| # | 项 | 不确定的后果 |
|---|---|---|
| 1 | **商用** | 商业项目侵权 |
| 2 | **嵌入 / 分发** | Webfont、App 内嵌常见踩坑 |
| 3 | **改作** | 改字重、改字形不一定允许 |
| 4 | **署名要求** | 漏署名违约 |

拿不到授权 → 标 `[待授权]`，不默认可用、不写进最终交付物。

## 4. 来源落盘（和《产物与来源规范》§6 对齐）

- 用户口述、粘贴、截图**都是来源**，默认原样存 `sources/`，记**出处 + 日期**；
- 外部链接记录 URL 与访问日期，不只写「网上找的」；
- 竞品案例必须给可核对的出处，**不编案例、不写「业内通常」**；
- 一条来源都没存也要在驱动卡写「无」，别留空。

## 5. AI 生成物的来源

- 记录：宿主能力或模型名、提示词版本、生成日期；
- 生成物不享有明确版权时，不承诺可商用，标「需法务确认」；
- 参考图 / 品牌标志由模型生成时，人工确认一致性，**不靠模型猜标准色与字形**；
- 生成物只作方向沟通素材时明确标注，见 `立体与空间交付边界.md`。

## 6. 新增资料的接入规则

1. 先核实许可并更新本表；
2. 只搬「可检索的规则 / 结构 / 检查表」，**不整包塞进技能目录**——工种包是自包含的，
   整包塞会串引用、破渲染校验；
3. 新增 `references/*.md` 必须登记进 `disciplines.json` 的 `shared_references`，否则校验判死文件；
4. 引入外部资料时，登记进 `disciplines.json` 并在本表记录，再跑 `build-disciplines.py` 重生成索引；
5. 外部规则与 `rules/设计通用规范.md` 冲突时，以本包规范为准。
