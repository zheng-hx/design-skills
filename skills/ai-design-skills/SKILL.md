# AI Design Skills — 设计师技能包唯一入口

> **本包对外只有一个技能**。无论你说「初始化 / 安装 / 更新设计技能」，都由本技能处理。
>
> 设计师技能是人的能力，默认装到**用户全局**：共享工作台 `~/.design/` + 注册到各 AI 工具的**用户全局技能目录**。
> 装一次，这台机器上所有项目、所有已用的 AI 工具都能调用。

---

## 一句话分流

| 用户说 | 走哪段 |
|---|---|
| 初始化设计技能 / 给项目装设计师 / 换工种 / 技能没生效（首次） | ① 初始化：渲染工作台 |
| 安装设计技能 / 命令没出现 / 换个工具也要能用 | ② 注册：按工具规则对账 |
| 更新设计技能 / 升级设计技能 / 重装一下 | ③ 更新：三层升级 |

> **边界**：本技能只写共享工作台 `~/.design/`（和当前项目的 `artifacts/` 目录），
> 并按规则把技能软链/复制到各 AI 工具的**用户全局技能目录**；不写工具根目录、不写旧版目录（如 `~/.codex/skills`）。

---

## 核心约定

```text
~/.design/                          ← 用户全局工作台（共享引擎，只存一份）
├── design.json                     #   版本 / 作用域 / 启用工种 / 路径
├── disciplines.json                #   全行业工种注册表（37 个）
├── rules/  templates/  references/ #   公共引擎与深度参考
└── skills/                         #   21 个工种 / 入口技能

<当前项目>/.design/artifacts/        ← 用户作品，按项目隔离，升级绝不覆盖
```

**为什么工作台全局、作品项目级**：规则和技能是通用的，一份就够；
设计稿、驱动卡、来源材料属于具体项目，混进全局会让 A 项目的稿子跑到 B 项目。

需要项目级工作台（团队共享、可提交进 Git）时加 `--scope project`，
它会把工作台放到 `<项目>/.design/`，其余行为一致。

**分层交付**：37 个工种里 19 个 `core` 做独立技能；18 个 `extended`
（室内 / 建筑 / 工业 / 服装 / 珠宝 / Logo / 印前等）只在 `工种索引.md` 登记，
由 `/design-any` 兜底——避免命令爆炸，也不假装 AI 能交施工图。

## ① 初始化：渲染共享工作台

### Step 1: 确认当前位置

- 以当前工作目录为「项目根」（只决定作品落哪，不决定工作台在哪）。
- 若当前目录是技能源仓库（存在 `skills/ai-design-skills/SKILL.md`），
  **停止**并提示用户到想干活的项目里执行。
- 若 `~/.design/design.json` 已存在，读它，展示当前版本、作用域与工种。

### Step 2: 确认工种（唯一允许的配置性提问）

**一次只问一句人话**，不要甩一张 37 项菜单：

```text
默认给你装 19 个高频设计工种的独立技能（UI/UX/品牌/平面/包装/插画/3D…），
长尾工种走通用兜底，够用吗？要是只做某几类，说下工种或场景就行。
```

| 用户回答 | `--disciplines` 传什么 |
|---|---|
| 「够用」「默认」「全装高频」 | `core`（默认） |
| 「全部都要，清单里 37 个都算」 | `all` |
| 「只做 UI 和品牌」 | 逗号分隔的 key，如 `ui-design,brand-design` |
| 说不出工种但描述了场景 | 从 `disciplines.json` 的 `triggers` / `summary` 反查，给推荐再确认 |

规则：先给推荐再留退路；**不追问**公司、产品、责任人、术语表、预算等信息。
已有工作台且工种集合变化时，提示「会重渲染管理区，项目作品不动」，请用户确认。

### Step 3: 渲染（一律走脚本，不手拍）

```bash
python3 <本技能目录>/scripts/render-design-package.py \
  --project <当前项目根> --scope user --disciplines <core|all|key1,key2>
```

脚本一次做完：

1. 生成 `design.json`（含 `scope` / `workbench` / `design_root`）+ 逐字复制 `disciplines.json`；
2. 渲染 `rules/` / `templates/` / `references/` / `skills/`，把共享资产路径注入 `{{DESIGN_ROOT}}`；
3. **保真核对**：除占位符替换外源文件逐行逐字一致，被改动直接退出；
4. 在暂存树跑 `verify-render.py`（引用可达 / 工种对账 / 无占位符残留 / 技能完整）；
5. 校验通过才整体替换工作台，旧目录先备份到 `~/.design.bak`；
6. 在当前项目建 `.design/artifacts/`（不存在才建，已有绝不动）。

> 校验不通过，工作台原样不动。只想验证不落盘时加 `--dry-run`。
> 测试想用临时主目录：加 `--home <临时目录>`，不会碰真实 `~/.design/`。

渲染完，直接继续 ② 注册到 AI 工具。

## ② 注册：按工具真实规则安装

> **先查看规则，再安装**。装错目录 = 技能不生效，这是「全局技能没生效」最常见的根因。
> 本技能默认 `--scope user`（用户全局）：装一次，所有项目都能用。

### Step 1: 先探测（只读，不写任何文件）

```bash
python3 <本技能目录>/scripts/probe-tool-dirs.py
```

输出每个工具：检测依据、该写哪个技能目录、目录是否已存在、本次是否写入。
`--scope project` 看项目级；`--tool workbuddy` 只看指定工具；`--json` 供脚本消费。

| 工具 | 用户全局技能目录 | 项目级技能目录 |
|---|---|---|
| **WorkBuddy** | `~/.workbuddy/skills` | `.workbuddy/skills` |
| **Codex** | **`~/.agents/skills`** | `.agents/skills` |
| Claude Code / Cline | `~/.claude/skills` | `.claude/skills` |
| Cursor | `~/.cursor/skills` | `.cursor/skills` |
| CodeBuddy | `~/.codebuddy/skills` | `.codebuddy/skills` |
| OpenClaw | `~/.openclaw/skills` | `.openclaw/skills` |
| Qoder | `~/.qoder/skills` | `.qoder/skills` |
| Reasonix | `~/.reasonix/skills` | `.reasonix/skills` |

**三个最常见坑（先记住）**：

1. **Codex 的全局目录是 `~/.agents/skills`，不是 `~/.codex/skills`**（后者是旧版遗留）。
2. **WorkBuddy 是 `~/.workbuddy/skills`**——旧版工具表完全漏了它。
3. **看项目内有没有 `.claude/` 是错的判据**：真实生效的是用户全局目录，
   而多数项目里根本没有这些点目录。检测依据应是 `~/.<工具>/` 是否存在。

完整规则与官方出处见 [AI 工具目录规则](../../docs/AI工具目录规则.md) 与
`skills/ai-design-skills/tool-dirs.json`（**单一事实源**）。

**硬规则**：

- ✅ **检测到的工具才写**，每个工具写自己对应的目录；
- ❌ **未检测到的一律不写、不创建目录**——只用 WorkBuddy 时绝不出现 `~/.agents/`；
  同时用了 Codex，才创建 `~/.agents/skills`；
- ❌ 不写工具根目录本身、不写 `~/.codex/skills` 这类旧版目录；
- ✅ 检测到的工具如果 `skills/` 子目录还不存在，**允许创建**它（很多工具从没建过）。

### Step 2: 一律调用对账脚本，不要手拍

```bash
python3 <本技能目录>/scripts/reconcile-skills.py --scope user
```

| 参数 | 作用 |
|---|---|
| `--scope user\|project` | 默认 `user`；项目级需显式指定 |
| `--tool <key>` | 只装指定工具，可多次；显式指定视为检测到 |
| `--home` / `--project` / `--workbench` | 覆盖路径（测试用，不碰真实主目录） |
| `--mode auto\|symlink\|copy` | 默认 `auto`，优先相对软链、失败回退复制 |
| `--no-entries` | 不注册本技能（唯一公开入口）；默认注册 |
| `--dry-run` | 只报告不落盘 |

**期望集合** = 工作台 `skills/` 下所有含 `SKILL.md` 的工种技能
**+ 本技能（唯一公开入口命令）**。入口一起注册，是为了换到任何项目都能调用「全局初始化」。

对账是**声明式、幂等**的：

| 现状 | 动作 |
|---|---|
| 在集合内且软链指向正确 | 保留 |
| 在集合内但过期 / 类型不一致 | 删除后重建 |
| 在集合内、工具目录里没有 | 新建 |
| 本包拥有但已不再集合 | 删除（清孤儿） |
| **不是本包拥有**（用户自己的技能） | **绝不碰**；同名冲突也跳过并告警 |

清单 `.design-managed.json` 记录 `scope`、`workbench`、`managed` 和**按技能记录真实 mode**
（修掉旧版幂等时把 `copy` 误记成 `symlink` 的问题）。

### Step 3: 输出安装摘要

```text
╔════════════════════════════════════════════════════╗
║   ✅ 设计技能已注册到 2 个 AI 工具（用户全局）      ║
╠════════════════════════════════════════════════════╣
║  WorkBuddy  ~/.workbuddy/skills   22 个 ✅ 软链      ║
║  Codex      ~/.agents/skills      22 个 ✅ 软链      ║
║  未检测到、未创建：Cursor / Qoder / Reasonix …       ║
║  工作台：~/.design/   作品：<当前项目>/.design/artifacts/ ║
╚════════════════════════════════════════════════════╝
重启会话或重载窗口后，/ui-design 等命令即可使用。
```

> 工作台不存在时脚本会明确报错，提示先跑 ① 初始化。

## ③ 更新：三层升级

> 设计师技能默认装在**用户全局工作台 `~/.design/`**，由本技能生成并注册到各 AI 工具。
> **首次执行 = 初始化，重复执行 = 升级。** 用户只需说一句「更新技能」，本技能走完整条链路。

### 三层过期，顺序永远是 ① → ② → ③

| 层 | 是什么 | 在哪 | 谁更新 |
|---|---|---|---|
| **① 本技能包** | 本技能文件（渲染 / 对账 / 入口） | 用户全局工具目录的软链源 = 技能源仓库 | 用户刷新源（git pull / 重新安装）后本技能重跑 |
| **② 共享工作台** | `~/.design/` 的规则 / 模板 / 参考 / 技能 / 注册表 | 用户主目录 `~/.design/` | 替换式重渲染 |
| **③ 工具注册** | 各 AI 工具**用户全局技能目录**的软链 | `~/.workbuddy/skills`、`~/.agents/skills` … | 扫描 + 对账（多退少补） |

> **① 没刷新，② 只能渲染出旧内容；② 没重渲染，③ 注册的是旧技能。**

### Step 0: 版本检测与分流（强制，先于任何写操作）

版本事实源：**`<本技能目录>/VERSION`**（住在技能目录里，因为
`npx skills add` 只拷技能目录，仓库根的 `package.json` 带不过去）。

| `~/.design/` | `design.json` 的 `package_version` | 模式 | 行为 |
|---|---|---|---|
| 不存在 | — | **未初始化** | 只刷新①，然后**询问**是否初始化；不得擅自生成整套 `~/.design/` |
| 存在 | 缺失（早期版本） | **补档升级** | 备份 → 替换管理区 → 保留用户区 → 补版本戳 |
| 存在 | `< 当前版本` | **升级** | 备份 → 替换管理区 → 保留用户区 → 写新版本戳 → 输出对比 |
| 存在 | `== 当前版本` | **已最新** | **不写任何文件**，输出「已是最新」；仅用户明确要求才强制重渲染 |
| 存在 | `> 当前版本` | **拒绝** | 立即停止：工作台由更新版生成，请先升级技能包，**不得降级** |

读不到 `VERSION` → 按 `unknown` 处理，**如实报告技能包可能不完整**，不静默继续、不编版本号。
**当前版本必须从①刷新后的技能目录重读**——刷新前读到的是旧版本。

### Step 1: 刷新本技能包（①）

**仓库地址从哪来（按优先级，不硬编码、不猜）**：

1. `~/.design/design.json` 中本包记录的 `source`（当初的安装地址，最可靠）；
2. 环境变量 `AI_DESIGN_SKILLS_REPO`；
3. 目标项目根 `skills-lock.json` 中本包记录的 `source`；
4. 都没有 → **明确报错并提示用户给出仓库地址**，不得编一个地址继续。

```bash
# 首选：重新 add —— 实测 update 补不上本包新增的入口技能
npx skills add <解析到的仓库地址> -y
# 只更新已装技能（不补新增）：
# npx skills check && npx skills update -y
```

> **实测结论**：`npx skills update` 只 "Checking N skill(s)"，**不会安装新增技能**；
> 从本地路径安装的技能无法 update（CLI 只认 git / 远程源）。
> 刷新失败**如实报告并停下**，不得假装已更新。

刷新后重读 `VERSION` 与新 `SKILL.md`；若版本高于正在运行的说明，按**新版说明**继续。

### Step 2: 替换式升级共享工作台（②）

一律走脚本，不手拍：

```bash
python3 <本技能目录>/scripts/render-design-package.py \
  --project <当前项目根目录> --scope user
```

- 省略 `--disciplines` 时**读已有 `~/.design/design.json` 的工种集合**，保持用户当初的选择；
- 脚本内置：暂存树构建 → 逐字保真核对 → `verify-render.py` 结构校验 → 整体替换；
- `artifacts/` 原样保留，旧 `~/.design/` 先备份到 `~/.design.bak/`（成功后才删）；
- 测试想用临时主目录：加 `--home <临时目录>`，不会碰真实 `~/.design/`。

### 管理区 / 用户区（升级契约）

| 类别 | 路径 | 升级时 |
|---|---|---|
| 管理区（生成物） | `~/.design/rules/`、`templates/`、`references/`、`skills/`、`design.json`、`disciplines.json`、`README.md` | 可整体重建 |
| **用户区（作品）** | **`<当前项目>/.design/artifacts/`** | **绝不覆盖、绝不删除** |

> 用户几个月的设计稿全在 `artifacts/` 里，这是升级最容易出事的地方。**不要绕过脚本手拍。**

### Step 3: 扫描并对账注册（③）

```bash
python3 <本技能目录>/scripts/reconcile-skills.py --scope user
```

- **按工具真实规则探测**：先找本机用户全局目录下有哪些工具根（`~/.workbuddy`、`~/.codex` 等），
  只向检测到的工具目录建软链；未检测到的一律不创建（只用 WorkBuddy 时绝不出现 `~/.agents/`）；
- 期望集合 = `~/.design/skills/` 当前技能 + **本技能（唯一公开入口）**；不在集合内的本包项删除（清孤儿）；
- 用户自己放进工具目录的技能**一律不碰**；
- 清单 `.design-managed.json` 与其他技能包的管理清单互不干扰；
- `--home <临时目录>` 可隔离测试，不碰真实全局目录。

### Step 4: 校验与一句话汇报

校验：`~/.design/design.json` 版本已是新版本 / 每个工具目录技能数与 `~/.design/skills/` 一致、
无孤儿无断链 / 用户现有项目的 `artifacts/` 一个 dossier 都没少。

**成功更新后只输出一句**，例如：

```text
已从 1.0.0 更新到 1.1.0：本次新增了 3 个设计工种与深色模式检查表，原有设计稿已保留，重启会话后生效。
```

规则：从新版 `CHANGELOG.md` 提炼**一个**最主要变化；一句内包含版本变化、主要更新、是否需重启；
不贴完整变更清单或长表格；备份路径、异常与失败原因不受此限，**必须如实说明**。

## 约束

- ❌ 不直接写 AI 工具技能目录根、不写工具根目录、不写旧版目录（如 `~/.codex/skills`）
- ❌ 向未检测到的工具目录写任何东西、不创建无关目录
- ❌ 不向用户收集公司、产品、责任人、术语表等非必要信息
- ❌ 不残留未解析的 `{{PLACEHOLDER}}`、不摘要式重写源文件、不手拍渲染
- ❌ 绝不删除或覆盖 `<当前项目>/.design/artifacts/`
- ❌ 不降级；版本未知不编造；仓库地址未知不编造
- ✅ 当前项目的 `.design/artifacts/` 绝不覆盖、绝不删除
- ✅ 工种集合以 `disciplines.json` 为准，不凭印象新增工种
- ✅ 默认 `user` 作用域；要项目级必须用户明确说，不擅自改
- ✅ 本技能（唯一公开入口）默认一并注册到工具全局目录
- ✅ 对账式：多退少补，不残留孤儿、不留断链
- ✅ 优先相对软链，回退复制，并记录真实模式
- ✅ 更新完说明「重启会话后生效」
