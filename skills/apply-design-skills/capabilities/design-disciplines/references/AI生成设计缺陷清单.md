# AI 生成设计缺陷清单

> **作用域**: **按需参考**。出稿后自查，评审时逐项对照。
> 这些是模型生成界面时反复出现的默认痕迹。**不是绝对禁止**，而是：采用时必须能说出品牌或场景上的理由。

---

## 1. 视觉

| 缺陷 | 为什么差 | 改法 |
|---|---|---|
| 紫色/靛蓝渐变作为默认主色 | 成了"AI 生成"的识别标志，与品牌无关 | 用品牌色；需要渐变时说明它表达了什么 |
| 玻璃拟态（模糊+半透明） | 降低对比度，损害可读性，且性能开销大 | 用实色 + 清晰层级；确实需要层次时用阴影或描边 |
| 发光阴影 / 霓虹描边 | 抢注意力，与内容层级无关 | 阴影只用于表达高度差，收敛到 1-2 级 |
| 圆角一律拉到最大 | 失去形状语义，也和紧凑型界面冲突 | 建立圆角令牌（如 4 / 8 / 12），按组件层级选 |
| 颜色数量过多 | 削弱信息层级，品牌感散 | 限制到「主色 + 中性色阶 + 1 个语义色」 |
| 灰底灰字的"极简" | 对比度不足，是可访问性失败 | 正文对比度 ≥4.5:1，见《可访问性细则》 |

## 2. 图标与装饰

| 缺陷 | 为什么差 | 改法 |
|---|---|---|
| emoji 当图标 | 跨平台渲染不一致，风格不受控，无障碍名混乱 | 用图标库；确无图标时用文字 |
| 每个标题/列表项都配装饰图标 | 视觉噪音，反而削弱真正需要强调的信息 | 只在图标能替代或强化文字时使用 |
| 装饰性分割线堆叠 | 用线条代替空白，界面变啰嗦 | 优先用间距表达分组，其次才是线 |
| 图标单独出现无文字 | 语义不清，且缺少可访问名 | 图标 + 文字；必需单独用时加 `aria-label` |

## 3. 布局

| 缺陷 | 为什么差 | 改法 |
|---|---|---|
| 什么都包一张卡片 | 卡片失去"独立单元"的语义，页面变成卡片列表 | 用间距和分组表达关系；卡片只用于真正独立的单元 |
| 卡片套卡片 | 层级混乱，内边距层层叠加浪费空间 | 一层卡片 + 内部用分隔与间距 |
| 每段都居中、内边距一样 | 没有视觉层级，扫读时找不到重点 | 建立层级：主标题/正文/次要信息的字号与间距递进 |
| 应用内出现 hero 区 | 把营销页结构搬进工具界面，挤走真正的功能 | 应用内首屏直接给用户要完成任务的内容 |

## 4. 数据与内容

| 缺陷 | 为什么差 | 改法 |
|---|---|---|
| 示例数据过于完美（张三、test@test.com） | 掩盖真实场景下的布局问题（超长名、多地区、特殊字符） | 用真实长度、多地区姓名、边界值 |
| 只有正常值，无空/极值 | 上线后由真实数据暴露问题 | 每个数据展示位都要想空值、1 条、极多、超长 |
| 数字左对齐、位数不对齐 | 无法快速比较 | 数字右对齐，等宽或表格数字 |
| 占位文案（Lorem ipsum 式） | 掩盖文案长度问题 | 写真实文案，哪怕先写草稿 |

## 5. 交互

| 缺陷 | 为什么差 | 改法 |
|---|---|---|
| 所有按钮视觉权重相同 | 用户不知道该点哪个 | 每屏一个主操作，权重明确 |
| hover 才出现的交互 | 触屏无 hover，键盘也可能不可达 | 提供点击/聚焦的等价入口 |
| 必须有鼠标的操作（拖拽排序等） | 键盘与移动端用户无法完成（违反 2.5.7） | 提供非拖拽替代方式 |
| 无意义的动效 | 拖慢操作，分散注意力 | 动效只用于表达状态变化或空间关系 |
| 每个操作都弹确认框 | 用户形成"闭眼点确定"的习惯，确认失效 | 可逆操作给撤销，不可逆才确认 |

## 6. 文案

| 缺陷 | 为什么差 | 改法 |
|---|---|---|
| 用内部术语/技术名词 | 用户看不懂 | 用用户的语言（WCAG 3.2.4 一致性） |
| 按钮写「提交」「确定」 | 不知道会发生什么 | 写清结果：「确认抵扣并支付」 |
| 错误只说「操作失败」 | 用户不知道怎么办 | 三段式：发生了什么 + 为什么 + 怎么办 |
| 同一功能多个叫法 | 认知负担 | 全局统一命名 |

## 7. 结构（最严重的一类）

| 缺陷 | 为什么差 | 改法 |
|---|---|---|
| 只画 happy path | 上线后异常全靠线上暴露，是最常见的返工来源 | 逐项补齐 8 个状态，见《状态与反馈细则》 |
| 异常流程画到一半就"以此类推" | 开发按自己理解实现，最终不一致 | 每条分支都要写清路径与恢复方式 |
| 只给视觉稿，没有规格 | 开发凭感觉还原，验收无依据 | 出「设计规格」：尺寸、令牌、交互、文案、验收口径 |
| 没有可测试的验收条件 | 无法判断做完没有 | 每条规格写成可验证的表述 |

## 自查三问

出稿后按顺序问自己三遍：

1. **这是什么** —— 遮住文字只看布局，能看出这是哪个产品的界面吗？（看不出 = 品牌感不足）
2. **空白在哪** —— 把所有装饰（图标、分割线、卡片边框）去掉，信息还清楚吗？（不清楚 = 依赖装饰而非层级）
3. **出错了会怎样** —— 把数据换成空、超长、极多，布局还站得住吗？（站不住 = 缺状态设计）

三条都能过，才算可以进入评审。
