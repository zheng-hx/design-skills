# Apply Design Skills — 全局初始化设计师技能

> **默认装到用户全局**：设计师技能是人的能力，不是某个项目的配置。
> 装一次，这台机器上所有项目、所有已用的 AI 工具都能调用。
>
> **边界**：只写共享工作台 `~/.design/`（和当前项目的 `artifacts/` 目录），
> **不直接写任何 AI 工具的技能目录**（那是 `/install-design-skills` 的职责）。

---

## 核心约定

```text
~/.design/                          ← 用户全局工作台（共享引擎，只存一份）
├── design.json                     #   版本 / 作用域 / 启用工种 / 路径
├── disciplines.json                #   全行业工种注册表（37 个）
├── rules/  templates/  references/ #   公共引擎与深度参考
└── skills/                         #   21 个工种 / 入口技能

<当前项目>/.design/artifacts/        ← 用户作品，按项目隔离，升级绝不覆盖
```

**为什么工作台全局、作品项目级**：规则和技能是通用的，一份就够；
设计稿、驱动卡、来源材料属于具体项目，混进全局会让 A 项目的稿子跑到 B 项目。

需要项目级工作台（团队共享、可提交进 Git）时加 `--scope project`，
它会把工作台放到 `<项目>/.design/`，其余行为一致。

**分层交付**：37 个工种里 19 个 `core` 做独立技能；18 个 `extended`
（室内 / 建筑 / 工业 / 服装 / 珠宝 / Logo / 印前等）只在 `工种索引.md` 登记，
由 `/design-any` 兜底——避免命令爆炸，也不假装 AI 能交施工图。

## 工作流程

### Step 1: 确认当前位置

- 以当前工作目录为「项目根」（只决定作品落哪，不决定工作台在哪）。
- 若当前目录是技能源仓库（存在 `skills/apply-design-skills/SKILL.md`），
  **停止**并提示用户到想干活的项目里执行。
- 若 `~/.design/design.json` 已存在，读它，展示当前版本、作用域与工种。

### Step 2: 确认工种（唯一允许的配置性提问）

**一次只问一句人话**，不要甩一张 37 项菜单：

```text
默认给你装 19 个高频设计工种的独立技能（UI/UX/品牌/平面/包装/插画/3D…），
长尾工种走通用兜底，够用吗？要是只做某几类，说下工种或场景就行。
```

| 用户回答 | `--disciplines` 传什么 |
|---|---|
| 「够用」「默认」「全装高频」 | `core`（默认） |
| 「全部都要，清单里 37 个都算」 | `all` |
| 「只做 UI 和品牌」 | 逗号分隔的 key，如 `ui-design,brand-design` |
| 说不出工种但描述了场景 | 从 `disciplines.json` 的 `triggers` / `summary` 反查，给推荐再确认 |

规则：先给推荐再留退路；**不追问**公司、产品、责任人、术语表、预算等信息。
已有工作台且工种集合变化时，提示「会重渲染管理区，项目作品不动」，请用户确认。

### Step 3: 渲染（一律走脚本，不手拍）

```bash
python3 <本技能目录>/scripts/render-design-package.py \
  --project <当前项目根> --scope user --disciplines <core|all|key1,key2>
```

脚本一次做完：

1. 生成 `design.json`（含 `scope` / `workbench` / `design_root`）+ 逐字复制 `disciplines.json`；
2. 渲染 `rules/` / `templates/` / `references/` / `skills/`，把共享资产路径注入 `{{DESIGN_ROOT}}`；
3. **保真核对**：除占位符替换外源文件逐行逐字一致，被改动直接退出；
4. 在暂存树跑 `verify-render.py`（引用可达 / 工种对账 / 无占位符残留 / 技能完整）；
5. 校验通过才整体替换工作台，旧目录先备份到 `~/.design.bak`；
6. 在当前项目建 `.design/artifacts/`（不存在才建，已有绝不动）。

> 校验不通过，工作台原样不动。只想验证不落盘时加 `--dry-run`。
> 测试想用临时主目录：加 `--home <临时目录>`，不会碰真实 `~/.design/`。

### Step 4: 输出摘要

```text
╔══════════════════════════════════════════════╗
║   ✅ 设计师技能已全局初始化                   ║
╠══════════════════════════════════════════════╣
║  工作台:     ~/.design/                        ║
║  启用工种:   19 个（core）                     ║
║  技能数量:   21 个（含路由与长尾兜底）         ║
║  用户作品:   <当前项目>/.design/artifacts/     ║
╚══════════════════════════════════════════════╝
下一步：执行 /install-design-skills 注册到你正在用的 AI 工具。
```

## 约束

- ❌ 不直接写 AI 工具技能目录、不写工具根目录、不写旧版目录（如 `~/.codex/skills`）
- ❌ 不向用户收集公司、产品、责任人、术语表等非必要信息
- ❌ 不残留未解析的 `{{PLACEHOLDER}}`、不摘要式重写源文件、不手拍渲染
- ✅ 当前项目的 `.design/artifacts/` 绝不覆盖、绝不删除
- ✅ 工种集合以 `disciplines.json` 为准，不凭印象新增工种
- ✅ 默认 `user` 作用域；要项目级必须用户明确说，不擅自改
