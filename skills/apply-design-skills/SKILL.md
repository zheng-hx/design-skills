# Apply Design Skills — 为项目生成设计师技能包

> 在**目标项目根目录**执行，生成 `.design/`——一个自包含的、可提交的设计师工作区。
> **边界**：只写目标项目内的 `.design/`，**不写任何 AI 工具目录**（那是 `/install-design-skills` 的职责），不写用户主目录，不扫描兄弟仓库。

---

## 核心约定

**一个项目 = 一个设计师技能包，包里按工种分技能。**
所有工种共享同一套引擎（交互节奏、状态机、评审、产物规范、人格、通用红线），差异只在各自的 `SKILL.md`。

```text
.design/
├── design.json              # 配置：版本 / 启用工种 / 产物目录
├── disciplines.json         # 全行业工种注册表（37 个）
├── rules/                   # 公共引擎 + 设计通用规范 + 人格
├── templates/               # 产物模板（含驱动卡 00-summary）
├── references/              # 按需加载的深度参考
├── skills/                  # 本次启用的工种技能
│   ├── design-router/       #   总入口：不确定找谁 / 跨工种
│   ├── design-any/          #   长尾工种通用兜底
│   └── <core 工种>/         #   19 个独立工种技能
├── artifacts/               # ⚠️ 用户作品，升级绝不覆盖
└── README.md
```

**分层交付**：37 个工种里 19 个 `core` 做独立技能；18 个 `extended`（室内 / 建筑 / 工业 / 服装 / 珠宝 / Logo / 印前等）
只在 `工种索引.md` 登记，由 `/design-any` 兜底——避免命令爆炸，也不假装 AI 能交施工图。

---

## 工作流程

### Step 1: 确认目标项目

- 以当前工作目录为目标项目根。若当前目录是技能源仓库（存在 `skills/apply-design-skills/SKILL.md`），
  **停止**并提示用户到待初始化的项目里执行。
- 若 `.design/design.json` 已存在，读它，展示当前工种与版本。

### Step 2: 确认工种（唯一允许的配置性提问）

**一次只问一句人话**，不要甩一张 37 项菜单：

```text
默认给你装 19 个高频设计工种的独立技能（UI/UX/品牌/平面/包装/插画/3D…），
长尾工种走通用兜底，够用吗？要是只做某几类，说下工种或场景就行。
```

| 用户回答 | `--disciplines` 传什么 |
|---|---|
| 「够用」「默认」「全装高频」 | `core`（默认） |
| 「全部都要，清单里 37 个都算」 | `all` |
| 「只做 UI 和品牌」「我们主要做包装」 | 逗号分隔的 key，如 `ui-design,brand-design` |
| 说不出工种但描述了场景 | 从 `disciplines.json` 的 `triggers` / `summary` 反查，给出推荐再确认 |

规则：

- **先给推荐再留退路**，不摆编号菜单，不把工种 key 当人话甩给用户。
- 这是**唯一**允许的配置性提问，确认后直接渲染；**不追问**公司、产品、责任人、术语表、预算等信息。
- 已有 `.design/` 且本次工种集合变化时，提示「会重渲染管理区，`artifacts/` 保留」，请用户确认。
- 用户要的工种是 `extended` → 如实说明它没有独立技能，会走 `/design-any` 通用流水线。

### Step 3: 渲染（一律走脚本，不手拍）

```bash
python3 <本技能目录>/scripts/render-design-package.py \
  --project <目标项目根目录> --disciplines <core|all|key1,key2>
```

脚本一次做完：

1. 生成 `design.json` + 逐字复制 `disciplines.json`；
2. 渲染 `rules/` / `templates/` / `references/` / `skills/`（按选定工种过滤）；
3. **保真核对**：除 `{{PLACEHOLDER}}` 替换外，源文件逐行逐字一致，被改动直接退出；
4. 在暂存树跑 `verify-render.py`（引用可达 / 工种对账 / 无占位符残留 / 技能完整）；
5. 校验通过才整体替换 `.design/`，`artifacts/` 原样保留，旧目录先备份到 `.design.bak/`。

> **校验不通过 `.design/` 原样不动。** 先修复源模板再重跑，不要绕过脚本手拍。
> 只想验证不落盘时加 `--dry-run`（在系统暂存区渲染，对目标项目零写入）。

### Step 4: 输出摘要

```text
╔══════════════════════════════════════════════╗
║   ✅ 设计师技能已生成                         ║
╠══════════════════════════════════════════════╣
║  生成目录:  .design/                          ║
║  启用工种:  19 个（core）                     ║
║  技能数量:  21 个（含路由与长尾兜底）         ║
║  长尾工种:  18 个，走 /design-any             ║
╚══════════════════════════════════════════════╝
下一步：执行 /install-design-skills 注册到当前 AI 工具。
```

## 约束

- ❌ 不写入任何 AI 工具目录、不写用户主目录
- ❌ 不向用户收集公司、产品、责任人、术语表等非必要信息
- ❌ 不残留未解析的 `{{PLACEHOLDER}}`
- ❌ 不摘要式重写源文件、不手拍渲染
- ✅ `.design/artifacts/` 绝不覆盖、绝不删除
- ✅ 工种集合以 `disciplines.json` 为准，不凭印象新增工种
